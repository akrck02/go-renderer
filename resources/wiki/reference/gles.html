gles

import "github.com/akrck02/go-renderer/gles"

Package gles draws go-renderer’s flat interfaces and a simple 3D scene through OpenGL ES, the graphics interface both browsers (as WebGL2) and Android phones offer. It makes no graphics calls of its own: it talks to a small interface, Functions, that each platform implements (the browser package through syscall/js, an Android window through golang.org/x/mobile/gl). So the renderers are written once, in plain Go with no cgo, and tested on any computer with a fake.

It uses only what OpenGL ES 2.0 has, plus 32-bit indices (an extension every current phone has): golang.org/x/mobile/gl knows nothing newer on Android, and WebGL2 accepts it all. So the shaders are GLSL ES 1.00, there are no vertex array objects (each draw describes its vertices) and the atlas is a LUMINANCE texture.

Desktop programs keep using the opengl and metal packages; nothing here replaces them.

SceneRenderer

SceneRenderer draws a scene.Scene in its simplest form: lit meshes and instances, the light of the time of day, fog, translucent water and, over them, the overlay (labels, header, notices and the program’s draw list). What a frame draws (culling, levels of detail, order) is planned by sceneplan, like on the desktop. It is a first step, not the desktop renderer: there are no shadows, sky dome, procedural patterns, waves, wind or snow. OpenGL ES 2 cannot draw instances, so each batch of instances is made into one mesh on the processor, again only when it changes.
