1. The audit before 1.0

Part of proposal 1, task T3 · Written 2026-10-22 · Author’s approval: phases A and B of the order proposed ☑ (2026-10-22, “Si”), for every package below; phases C and D ☑ (2026-10-22, “arreglalas todas”), with the decisions in phases C and D.

How it was done

Every package was read against llm-guidelines (and its Go and docs chapters) and against the proposal’s two imperatives: a simple, efficient API (is the public API the smallest that does the job? what would a newcomer stumble on?) and performance (what does a frame cost, where does it allocate?). Three tools helped the reading:

  • a small syntax-tree scan of every .go file, whatever its build tags: functions over 40 lines, names of one or two letters, abbreviations, errors.New/fmt.Errorf, panic, printing, exported names without a comment;
  • the baseline benchmarks and memory profiles of the frames that still allocate;
  • go doc of each package, and the imports of go-ui and go-engine, to know who uses what.

Nothing was changed while auditing. Line numbers are those of commit 2adf4ce.

Hand-written code. The Renderer contract and models, the graphics maths, the first OpenGL work (opengl/opengl.go, opengl/renderer.go, opengl/window.go, loaders/glb.go), the root main.go and the software, vulkan, webgpu and metal stubs are the author’s. Their findings are listed like the others but marked ✋ author’s decision: this audit proposes, it does not plan to rewrite them.

Severity: high breaks a rule that costs users or frames today, or blocks 1.0’s promise; medium is a rule broken where a newcomer would stumble; low is polish. Effort: S under a day, M a few days, L a week or more.

The ten findings that matter most

  1. graphics.Vec4 and graphics.Mat4 are the shorthand the guidelines name by example (Vector, not Vec3). They are the most used names of the module (go-ui 35 uses, go-engine 42). ✋ Hand-written: renaming is the author’s call, and the largest breaking change of 1.0.
  2. A frame still allocates. Planning the sample island: 2 allocations (288 B), both a scene.Node made for the water every frame (sceneplan/commands.go:161, :176). The overlay: 1 (sort.SliceStable in opengl/overlay/layout.go:243). An OpenGL 2D frame: 3–4 (gl.Ptr and GetIntegerv taking addresses in opengl/overlay.go:263, :110). All four can reach zero.
  3. No error has a code outside the stubs: 64 errors.New/fmt.Errorf in 27 files, plus metal.ErrUnavailable and browser.ErrNoCanvas/ErrNoWebGL2 that are plain sentinels.
  4. Library code panics, logs and prints. opengl/opengl.go:129–149 and opengl/window.go:14,43 panic (✋); opengl/renderer.go:282 calls log.Fatalf (✋); loaders/glb.go:103–180 prints every mesh (✋); opengl/opengl.go:162 and viewer/viewer.go:434 print. A program cannot silence or handle them.
  5. models is a package named for a kind of file, and models.Application carries window settings, frame callbacks, input and the immediate-mode matrices in one struct (models/application.go:59). models.Camera belongs in camera. ✋ Hand-written core.
  6. sceneplan exports 32 functions and 21 types that only the module’s backends use (InterleaveVertices, ScaleOrOne, ColorOrWhite…). As internal/sceneplan, the public API shrinks by a third and nothing outside breaks (go-ui and go-engine import none of it).
  7. viewer.Run(world, options, title, update, loadingTime): loadingTime only feeds the benchmark printout, yet every caller must pass it. Options mixes start-up view, rendering switches and benchmark settings in 20 flat fields.
  8. input.State is one struct for two audiences: programs read it (Pressed, Clicks), and backends write it (SetKey, MoveCursor, AddCharacter, PressBack…). A newcomer reading go doc input.State sees 56 methods, half of which they must not call.
  9. Global mutable state in libraries: overlay.UseFonts sets a package variable (opengl/overlay/fonts.go:41), overlay.FontFolders reads the home folder at import (fallback.go:26), android.Channel and android.Tones are exported variables, and opengl.firstFrame (opengl.go:156) is shared by every window.
  10. Generic names: ctr speaks the device (OpenBottomScreen, BottomWidth, Slider3D, CStick, PICAMatrix), where the guidelines ask for OpenSecondScreen, RightStick. The package name ctr itself is the console’s code name, an abbreviation to a newcomer.

Order proposed

  1. A — No breaking change, frame cost first ☑ approved (S each): the four allocations to zero (sceneplan, opengl/overlay, opengl), each with an AllocsPerRun test; error codes in every AI package; no prints in AI code; test names.
  2. B — Shrink the API without breaking outside ☑ approved (S–M): internal/sceneplan, shaders to their backends, windowloop’s re-exports, overlay fonts as an option.
  3. C — Breaking, AI-written (awaits the author) (M each): viewer.Run, input’s backend side, ctr → nintendo3ds, camera.Plan → Map, loaders names, android services.
  4. D — The author’s code (✋, awaits the author): Vec4/Mat4, models, the panics and prints of the first OpenGL work, LoadGLB, the Metal stub. Decided by the author, ideally together, because they are 1.0’s largest break and go-ui and go-engine should move once.

Phases A and B: what was done (2026-10-22)

A — nothing breaks, frame cost first.

  • No frame allocates. Planning the sample island (the water’s nodes are kept), laying out the overlay (labels sorted with slices.SortStableFunc into a reused buffer) and an OpenGL 2D frame with lights and a blurred backdrop (what GL fills through a pointer lives in the renderer; vertices go to GL as a pointer to their first value) all make no garbage. Each has a testing.AllocsPerRun test; the numbers are in the optimization plan.
  • Error codes in every AI-written package, each in its errors.go with a test: overlay.font-not-read, opengl.framebuffer-incomplete, windowloop.not-on-main-thread, gles.shader-not-compiled/program-not-linked, draw2d.invalid-colour/image-not-decoded, loaders.file-not-read/invalid-gltf/unsupported-accessor/image-not-decoded, viewer.invalid-point/unknown-backend, metal.unavailable/shader-not-compiled/ nothing-captured, browser.canvas-not-found/webgl2-missing, android.video-not-opened, ctr.screen-not-opened/invalid-shader/invalid-vertices/out-of-linear-memory. metal.ErrUnavailable stays as a deprecated alias of metal.Unavailable (Go UI checks it); browser.ErrNoCanvas and ErrNoWebGL2 were used by nobody and were replaced.
  • No printing in AI-written library code. Problems a frame works around go to overlay.Painter.Report: the program’s Warn when it sets one, otherwise the default slog logger, which the program chooses. The viewer shows the walking speed and the fall back from Metal as notices. (On the 3DS, log/slog adds about 42 KB to a .3dsx.)
  • Comments on every public name of the AI-written packages; tests call their *testing.T test; the overlay’s Audit… benchmarks are named for what they measure.
  • Repository. .gitignore covers .env, out/ and .3dsx builds. The compiled .shbin shaders stay in git: go:embed needs them, and a program importing ctr should not need devkitPro. go generate ./ctr assembles them again with picasso, byte for byte the same.

B — a smaller API, nothing broken outside.

  • sceneplan is internal/sceneplan.
  • The OpenGL shader sources live in opengl, unexported; what every backend’s shaders agree on (SharpPictureOffset, AmbientLight, the backdrop blur’s weights) is internal/shading. graphics keeps the maths (and the author’s shaders.go).
  • windowloop no longer re-exports frameloop’s clock.

Go UI and go-engine build and pass their tests against this branch (desktop, WebAssembly and Android vetted; a go-engine game built for the 3DS).

Not done in A and B, and why.

  • Phase C (breaking): fonts as an option of NewPainter (the global UseFonts, and FontFolders/PrebuiltCharacters read at import, would have to go, and Go UI calls UseFonts); draw2d.Hex → MustHex; scene.ColorFromHex, DefaultNoticeSeconds; the rest of the order’s third step. Test names as sentences (TestRectIntersect…) wait for each package’s rewrite.
  • Not breaking, but not API: splitting windowloop.Run and its tests (R7), camera.Plan’s magic numbers.
  • Phase D (the author’s code), left as it was: the panics and prints of opengl/opengl.go, opengl/window.go and opengl/renderer.go (CompileShader, LinkProgram and the texture loader return text errors, call log.Fatalf or panic); loaders.LoadGLB’s prints and text error; the metal stub’s “Graphics API not implemented yet!”; comments on the public names of models, graphics (space.go, shaders.go), opengl/renderer.go and the stubs; the root main.go. Two AI-written lines inside opengl/opengl.go were changed: StartLoop’s main-thread error (marked for codes above) and its calls of windowloop’s clock, now frameloop’s.

Phases C and D: what was done (2026-10-22)

The author’s decisions (2026-10-22, “arreglalas todas”): phase C in full; phase D on his own code, which he explicitly authorised: Vec4/Mat4 (and any shorthand like them) become Vector and Matrix with x, y, z, w kept; one- and two-letter names become words; models is dissolved by meaning (camera.Camera; Application split into the window’s options, the callbacks and the state, with the smallest API); the Renderer contract stays, cleaned (names, comments, coded errors), its four stubs returning their not-implemented codes; the panics, log.Fatalf and prints of opengl.go, window.go, renderer.go and LoadGLB become coded errors; LoadGLB is split; the root main.go loses its panic and gains a -backend flag; the Metal stub returns a code; every public name has a comment; gles’s GL vocabulary gets readable names, the GL name in each comment. On the 3DS the warning channel must not link log/slog (about 42 KB a .3dsx). And, over everything: never slower nor allocating more than the After A/B column, and no frame allocates.

C — breaking, AI-written.

  • overlay.UseFonts and FontFolders are gone: NewPainter(Fonts), NewMeasurer(Fonts) and every renderer that paints text take an overlay.Fonts, whose zero value is the default and whose Folders say where the system’s fonts are (DefaultFontFolders()). Nothing is read or built at import; two windows can draw in two fonts.
  • draw2d.Hex is MustHex (Go’s name for “panics on a bad constant”); draw2d.Rect is Rectangle. scene.ColorFromHex is gone (draw2d.ParseHex reads the short #rgb too). DefaultNoticeDuration is DefaultNoticeSeconds; the material kinds end in Kind (LitKind…), as draw2d’s do.
  • input.State keeps what programs read; what backends write is on state.Feed(), a value that costs nothing (tested). The sticks are Stick() and RightStick(); MultiClickDistancePixels says its unit.
  • viewer.Run(world, options, title, update): no loadingTime (it is Measure.LoadingTime). Options has Start, Rendering and Measure; a benchmark writes to Measure.Output; the Usage constant is gone (the flag set lists the flags).
  • ctr is nintendo3ds, with generic names: OpenScreen, OpenSecondScreen, SecondScreenWidth, DepthSlider, a reading’s Stick/RightStick, GPUMatrix. One way each: Reading.Pressed (no ButtonsPressed nor Controls.Pressed), BeginFrame/EndFrame (no screen copies, no BeginStereoFrame). The 3DS examples’ mains are split.
  • windowloop.Run is a loop of small steps, tested (the resize follower, drawing on demand, when a frame is due, the title’s count); the frames per second appear in the title only when the application sets ShowFramesPerSecond.
  • camera.Plan is camera.Map; its numbers and the orbit’s are named; the constructors take float32.
  • loaders.ParseSceneGLB is ReadScene(io.Reader).
  • android.Notify takes its Channel (MessagesChannel()); the palettes’ tones are private.
  • Test names read as sentences where they did not.
  • On the 3DS the overlay warns with a line on the console instead of log/slog.

D — the author’s code, refactored at his request.

  • graphics.Vector and graphics.Matrix, whole words inside (radians, column, result, fieldOfViewRadians); Move works in place; Inverse says when it fails; a test per transform. The author’s shader sources moved into opengl, unexported.
  • models is gone: window.Application (Options, Callbacks, and the state: Input, Renderer, Camera, Stop, the matrices), window.Backend (Run, Draw; was GraphicsApi with StartLoop), immediate.Renderer/Mesh/Model, camera.Camera (FieldOfViewRadians float32, named defaults). The backend enumeration is gone: its only user was main.go, which now maps the -backend flag to a backend.
  • The contract: RenderObject and RenderModel (were Render3dObject, Render3dModel), centre for a rectangle’s or picture’s position, a comment on every method. Every backend is <backend>.Window and <backend>.Renderer; the stubs, Metal’s included (metal.not-implemented), return their codes, tested.
  • OpenGL: opengl.Window returns opengl.window-not-opened, context-not-started, shader-not-compiled, program-not-linked, frame-not-saved; no panic, log or print; the hidden arrow-key and WASD camera is gone; the window fills the renderer and defaults itself; SaveFrame reads, flips and encodes in three functions; the immediate renderer keeps its buffers (a shape allocates nothing on the Go side) and says opengl.not-implemented for the shapes it cannot draw yet, instead of drawing nothing silently. The unused newTexture (the log.Fatalf) is gone.
  • loaders.LoadModel (was LoadGLB) is built on the glTF reader: small functions, every component type, no prints, coded errors.
  • main.go: -backend opengl|software|vulkan|metal|webgpu, errors returned and shown; the camera steps back so the triangle shows.
  • gles.Functions reads in words (SetUniformInteger, SetTextureImage, DescribeVertexAttribute), each comment naming the OpenGL ES function.

Performance. Every benchmark was run again (After C/D). Two had grown by 1–23 % from changes elsewhere in the binary, and were won back with real work: ordering a list’s commands and moving a box’s corners. Clipping quads now keeps those wholly inside the clip without copying them, and a character is looked up once in its own face instead of twice: a busy application frame paints in 124 µs (149 at A/B). No frame allocates, and the tests that say so pass.

3DS size. The .3dsx files, before → after: triangle3ds 458 444 → 412 712 bytes, island3ds 518 028 → 472 092, lamps3ds 506 904 → 460 868, lights3ds 2 272 004 → 2 137 272 (43–135 KB less each, most of it log/slog).

Not done, and why.

  • android’s platform services in a package of their own (notifications, sharing, links, haptics, video, palettes). Their C talks to the activity’s JNI side; moving it across two cgo packages means sharing C symbols and the Java VM between them, which builds but can only be proved on a phone, and no device was at hand. The mutable globals the audit named are gone.
  • Metal: the darwin files were changed by hand and read twice, but they cannot be compiled here (no macOS SDK): they need a build on the author’s Mac.
  • draw2d.Command.Text doubling as an icon’s name is documented, not split: a second field would add 16 bytes to every command.
